# UI Copy Minimalism

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

UI 只保留帮助用户理解、判断或完成操作的必要文案。删除重复说明和装饰性文字。

## 一条判据

对每一处可见文字问三个问题，任一为「是」就删掉或合并：

1. 删掉后，用户会看不懂、选错或做不成吗？不会 → 删。
2. 它是否重复了标题、标签、占位符、按钮或旁边另一句话？是 → 合并成一句更清楚的话。
3. 它是否只是在夸产品、营造氛围或填充空间？是 → 删。

## 操作顺序

1. **盘点**：列出界面上所有可见字符串（标题、副标题、标签、帮助文本、占位符、按钮、空状态、提示、脚注）。
2. **归组**：同一意思的文字只留一处，选信息密度最高的位置（通常是标题或控件标签）。
3. **删**：按上面的判据逐条删除，先删整句，再删半句。
4. **补结构**：删掉解释后若产生歧义，用布局补：分组、间距、分隔线、顺序、图标、默认值、格式约束。不要用一句话补。
5. **守底线**：确认删除没有带走必需信息（见下节）。
6. **交付**：给出改前 → 改后的对照，只列实际改动，不额外写设计说明。

## 必须保留

删除的是解释，不是风险与约束。以下内容不因「精简」而删：

- 错误的**原因 + 恢复方式**（「文件超过 20 MB，请压缩后重试」）
- 不可逆操作的**后果**（「删除后无法恢复」）
- **单位、格式、范围、限制**（字符上限、支持的文件类型、计费周期）
- **权限与可见范围**（「仅自己可见」）
- 空状态的**下一步操作**（一个按钮即可，不必写说明段）
- 法律、安全、合规要求的固定文案

## 常见可删项

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 复述标题的副标题 | 「设置」+「在这里管理你的设置」 | 删副标题 |
| 复述标签的帮助文本 | 「邮箱」+「请输入你的邮箱地址」 | 删帮助文本 |
| 复述占位符的说明 | 占位符 `搜索项目` + 下方「可按名称搜索项目」 | 删说明 |
| 客套与语气词 | 「请」「温馨提示」「需要注意的是」 | 删，直接说事 |
| 营销形容词 | 「强大的」「一站式」「极致体验」 | 删 |
| 重复的状态描述 | 徽标「已保存」+ 文字「你的更改已保存」 | 留一个 |
| 同一动作的两种叫法 | 按钮「提交」、提示「点击提交按钮完成提交」 | 统一为一个动词 |
| 已由控件表达的必填/可选 | 输入框已有 `*`，仍写「此项为必填」 | 删（除非会影响判断） |

## 让布局解释

文字删掉后，优先用这些手段表达原意：

- **邻近**：标签紧贴它描述的控件，替代「以下选项用于……」。
- **分组与间距**：用留白和分隔线区分区块，替代「第一部分 / 第二部分」。
- **顺序**：按用户决策顺序排列，替代流程说明。
- **控件形态**：开关、分段控件、默认值本身就在说明可选项。
- **就地约束**：字数计数、格式示例放在输入框内，替代一段规则说明。
- **渐进披露**：次要解释放进 tooltip、帮助面板或展开区，不占主界面。

## 改写示例

- 「欢迎回来！请输入您的账号信息以继续登录。」→ 「登录」
- 「通知设置」/「在这里你可以配置你希望接收的通知类型」→ 「通知」，下面直接是开关列表
- 「暂无数据」/「你还没有创建任何项目，创建项目后可以在这里查看和管理。」→ 「还没有项目」+ 按钮「新建项目」
- 「删除」/「此操作将永久删除该项目，删除后所有成员将无法访问。」→ 确认框标题「删除项目？」+ 正文「所有成员将立即失去访问权限，无法恢复。」
- 「高级设置（可选）」→ 「高级设置」，可选项在控件上标注

## 验收

- 主界面上没有一句话在解释另一句话。
- 每个区块只有一个标题层，没有「标题 + 副标题 + 说明」三层。
- 每个动作只有一个动词，全界面叫法一致。
- 删完仍需判断的地方，是布局问题，不是文案问题——改布局，不要加字回去。
